# Test Setup Contract: Reports Run History  (area: Reports)

Spec file: `tests/ui-testing/playwright-tests/Reports/reportHistory.spec.js`
Generated by The Analyst (Phase 1). The Engineer implements setup from these exact patterns; the
Healer/Refiner consult this before touching a data/setup failure.

## Data conditions each behavior needs

1. **Org-wide History tab renders** — needs an org id only (no data). Read-only.
2. **Run now → manual row appears at once** — needs a report whose "Run now" succeeds WITHOUT SMTP.
   => a **cached** report (`destinations: []`) bound to a dashboard. Cached "Run now" warms the
   dashboard cache and sends no email (no SMTP server required in CI).
3. **Run drawer opens / outcome / trigger cell** — needs that same manual run to exist (produced by
   Workflow 2's trigger response, which carries the run row before the stream copy is searchable).
4. **Empty "no runs yet"** — needs a report with zero runs (a freshly created report).
5. **Filtered empty ("No runs in this range")** — needs the same run, then a filter that matches
   nothing (e.g. select the "skipped" tile, or a 24h range older than the run).
6. **Status chips / cached tile / edit-recipients-hidden** — needs a cached run; `show-cached-tile`
   is on in both the org view and the per-report view when the report has no destinations.

## Streams / data the spec must establish

- `<DASHBOARD_NAME>` **[per-test]** — minimal v8 dashboard (report source). Fields: none required
  (empty panels). Why: every report needs a dashboard to render.
- `<REPORT_NAME>` **[per-test]** — cached dashboard-bound report. Key fields:
  `destinations: []` (this is what makes it "cached" and SMTP-free), `enabled: true`,
  `frequency: { interval: 1, type: 'once' }`, one dashboard with `report_type: 'pdf'`,
  `timerange: { type: 'relative', period: '30m' }`. Why: Workflows 1–5 all operate on this report
  and its run.

No streams/ingestion needed — report history reads the backend's report-run stream internally
(not a user stream). Do **not** ingest logs/metrics for this feature.

## How to create it (copy these EXACT patterns — do NOT invent setup)

- Dashboard: `createDashboardViaApi(pm.apiCleanup, DASHBOARD_NAME)` —
  see `tests/ui-testing/pages/dashboardPages/dashCreation.js:197-248` and its use in
  `tests/ui-testing/playwright-tests/Reports/reportHistory.spec.js:25`.
- Cached report: `createDashboardReportViaApi(pm.apiCleanup, { reportName: REPORT_NAME,
  dashboardId: dash.dashboard.dashboard_id, tabId: dash.dashboard.tabs?.[0]?.tab_id || 'default',
  cached: true })` —
  see `tests/ui-testing/pages/reportsPages/reportCreation.js:157-225` and use in
  `reportHistory.spec.js:28-33`.
- Navigation (org view): `page.goto(\`${ZO_BASE_URL}/web/reports?org_identifier=${ORGNAME}&tab=history\`)`
  OR `pm.reportFoldersPage.navigateToReports()` then click `[data-test="tab-history"]` —
  see `reportHistory.spec.js:71-73` and `reportFoldersPage.js`.
- Run now (UI): open report detail → click `[data-test="reports-reportdetail-run-now"]` → confirm
  `[data-test="o-dialog-primary-btn"]` — see `reportHistory.spec.js:49-50`.
- Auth/org: the worker auth state is already established by `navigateToBase(page)` (fixture
  `../utils/enhanced-baseFixtures.js`); `pm.apiCleanup` is `new APICleanup(page)` (authenticated,
  `api._fetch` uses `api.authHeader`, `api.org`). `ORGNAME`/`ZO_ROOT_USER_EMAIL` come from env.
- Cleanup: `pm.apiCleanup.deleteReport(REPORT_NAME)` + delete the dashboard(s) by title prefix
  (`apiCleanup.fetchDashboardsInFolder` / `deleteDashboard`) — see `reportHistory.spec.js:78-86`.

## Timing / load-state gates (the run's data arrives async)

- The **manual run row appears immediately** from the trigger response (memory ref), so the first
  status chip is visible without waiting for the stream copy:
  `await expect(page.locator('[data-test="reports-reportrunhistory-status"]').first()).toBeVisible({ timeout: 120000 })`.
- The **trigger-source cell** may take a moment to hydrate; assert on
  `reports-reportrunhistory-table` + `o2-table-cell-trigger_source` `.first()` after the status chip
  is visible (existing spec does exactly this, `reportHistory.spec.js:53-60`).
- If asserting the **server-paginated** rows (not the optimistic row), wait for the
  `/api/v2/{org}/reports/history` GET response before asserting row content — the query refetches
  after a manual run (see `afterManualRun` at `ReportRunHistory.vue:562-566`).

## Preconditions / toggles

- Report must be **cached** (`destinations: []`) so "Run now" needs no SMTP. A report with an email
  destination will try to send and fail in CI (no SMTP) — producing an `error` run, which is a
  *different* (valid but flakier) assertion.
- History is only enabled when the backend does NOT return `disabled_reason`. OSS CI runs
  `usage_reporting_mode` ≠ `remote` by default, so history is enabled. If the disabled empty state
  (`reports-reportrunhistory-disabled`) appears, the deployment is in remote reporting mode — park,
  do not retry the assertion.
- The report filter select (`reports-reporthistory-report-select`) is only present in the **org-wide**
  view, not the per-report detail view.

## Gotchas (so the Healer/Engineer don't rediscover them)

- **Cached vs sent:** `createDashboardReportViaApi` with `cached: true` writes `destinations: []`.
  The drawer's "Edit recipients" button is then hidden (`v-if="canEdit && !run?.is_cached"`); a
  test that asserts it must use a **non-cached** report (which then needs SMTP for a clean "Run now").
- **Trigger-source filter items have no data-test** — `all`/`scheduled`/`manual` toggle items in
  `ReportRunHistory.vue:109-117` are unlabeled; locate by text or add the selector (see the design
  doc "NEEDS SELECTOR").
- **The manual row is optimistic** and TTL-bound (`MANUAL_RUN_TTL_MS = 5 min`,
  `reportRun.ts:104`); it is filtered out once the stream copy becomes searchable
  (`searchableRunKeys`). Assert on it right after the trigger, not after long delays.
- **`isFiltered`** treats the default `7d` and widened `30d` as "not a filter" — so a fresh report
  with no runs shows "No runs yet", not "No runs in this range", even on the 7d default.
- **Report name cells are per-name** (`report-list-name-cell-${name}`) and may race the row render;
  use `reportRow(name)` (`reportsPage.js:115-116`) for row-scoped actions.
- **Cleanup ordering:** delete the report BEFORE deleting its dashboard (a report references the
  dashboard); the existing spec does report-then-dashboard.
