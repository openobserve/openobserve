# Refresh button — manual test plan

Branch `feat/fe-caching`. Covers every refresh button moved to the inline layout
(`ORefreshButton layout="inline"`): **36 buttons in 36 components**. 35 can be reached in the UI;
1 cannot (see §6).

Every page, click path, request and shortcut below was read from the code on this branch.

---

## 1. Before you start

1. **Build:** most pages below are enterprise pages. Use an enterprise build. LLM Model Pricing
   and LLM Providers also exist on cloud.
2. **Org:** use a normal org (for example `default`) for everything except **Nodes**, which only
   exists in the `_meta` org (§3, row 7).
3. **Open DevTools → Network**, filter **Fetch/XHR**. You will count requests per click.
4. **URLs** in the tables are relative to the app root, e.g. `<app>` = `http://localhost:5080/web`.
   Always keep `?org_identifier=<org>` on the URL.
5. **Data:** a page with no rows still has to show its button, except where the table says
   otherwise. For the row checks (C6), have at least one row on the page.
6. **Cache tiers:** Tiers re-set 2026-09-15: 1 min live / 5 min medium / 1 h normal; gcTime 3 h
   for all. The **Cached for** column below carries the new value, with the old one in brackets.

## 2. What every refresh button must do

Run these on **every** page in §3–§5. The tables only list what is different per page.

| #   | Check        | Expected                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | Look         | Outline button with a refresh icon. After the first successful load: a thin divider and an age label next to the icon. Same height as the button beside it (usually the column-toggle button). Check light **and** dark theme.                                                                                                                                                                                   |
| C2  | Age label    | `just now` (under 5 s), then `12s ago`, `3m ago`, `1h ago`. It updates by itself about every 10 seconds.                                                                                                                                                                                                                                                                                                         |
| C3  | Tooltip      | Hover: `Last refreshed: <local time>`. | C4  | Click        | Sends exactly the request(s) in the table's **Click sends** column. The icon spins while the request is running. When it answers, the label becomes `just now` and the tooltip time updates.                                                                                                                                                                                                                     |
| C5  | Double click | Clicking again while it spins does nothing: no second request.                                                                                                                                                                                                                                                                                                                                                   |
| C6  | Rows         | The rows stay on screen during the refresh. The table must not go blank or show skeleton rows. Exceptions are marked **Existing page behaviour** in their rows (20, 24, 28, 34, 35): those pages already showed skeletons on refresh before this change.                                                                                                                                                         |
| C7  | Keyboard `r` | Only where the **`r`** column says ✓. Click on the page background (not in a text box) and press `r`: same result as C4. Typing `r` inside the search box must **not** refresh.                                                                                                                                                                                                                                  |
| C8  | Revisit      | Load the page, go to another page, come back within the **Cached for** time: **no** new list request, and the label keeps counting from the first load (for example `40s ago`). It does **not** reset to `just now`. Come back after that time: one request, label becomes `just now`. Switching browser tabs or windows and coming back never sends a request by itself (focus refetch is off for every query). |
| C9  | Failure      | Make the request fail (DevTools → Network → **Offline**, then click). The label does not move, the rows stay, an error toast may appear. Go back online and click: it recovers.                                                                                                                                                                                                                                  |

not cloud. Every row was driven through the real page: the refresh time was compared with the
query cache entry, requests were counted from the network, a slow response was simulated for

**Fixed during the run — row 26 after a reload.** When the enrichment table list is restored from
the saved copy, TanStack Query first stamps the entry with the current time and the persister
corrects it to the saved time in a later notify flush. Enrichment Tables read the time once, straight
after the read resolved, so it kept the temporary current time and showed `just now` for rows up to
5 minutes old. `useStreams.getStreamsFetchedAt` now waits for that flush before reading, which also
covers the unused `AssociatedStreamFunction`. Re-checked in the browser: after a reload the label
shows the saved copy's age (`37s ago`), matches the cache entry, and no table-list request goes out;
refresh and revisit still pass. A unit test restores a real saved copy and fails without the fix.
